
# StereoBoy Firmware

Open-source firmware for StereoBoy, the portable & modular stereo system!

## What is this?

### FULL DISCLAIMER: I use AI-generated code for parts of this project! All design and engineering choices are mine and mine only. AI was used mainly for debugging and optimization.

<img width="512" alt="image" src="https://github.com/user-attachments/assets/b3de6a4b-a93e-4ea9-a027-3ca3d14be135" />

StereoBoy is a portable audio player I designed to be fit inside an original GameBoy Pocket shell. Read more about it here: [Hackaday Project Page](https://hackaday.io/project/205771-stereoboy)

**My main focus on the software side is providing a no-BS listening experience. For me, this implies a few things:**

 - Instant boot-up time
 - Intuitive UI that should ideally be easy enough to use without a manual
 - Simple, snappy UI that provides quick navigation between tracks, albums, artists, etc.
 - Easy to load music, with no software to manage file transfer
 - Plus the usual features such as an album art, equalizer, fast forward/rewind, etc.

So far, I've achieved sub-1s boot time that instantly provides a simple, iPod-like menu for albums, artists, and tracks as soon as you turn the device on, with a snappy interface that allows navigating through thousands of tracks with zero noticeable lag.

Music is loaded simply by dragging and dropping audio files on a micro-SD card, although a python script needs to be run to update the system cache with new track metadata. The script takes about 1.5 minutes to parse through a library of a little over 2000 songs. Thanks to the pre-generated metadata cache files, StereoBoy can instantly load fully sorted menus and crisp album artwork pretty much instantaneously.

Currently I have a very rudimentary equalizer going as well as buttery smooth fast forward/rewind. MP3s are the only supported file format, but I plan on adding FLAC support too.

**However, I also wanted to add some of my own personality to give the firmware some charm. Examples include:**

 - warp effect when pausing/resuming to simulate an analog tape reel. It's my favorite part of the entire project and never ever gets annoying.
 - Oscilloscope visualizer that displays super-high FPS waveforms of left and right channel audio
 - Audio plays at slightly lower speed and pitch on low battery to simulate a dying walkman (work in progress!)

## Let's get technical
### Here's a simple block diagram of the firmware architecture:

<img width="512" alt="asdf" src="https://github.com/user-attachments/assets/f252040d-069f-4423-93b9-0fdcb8262909" />


The firmware runs in a producer-consumer architecture, with Core 0 acting as the producer and Core 1 as the consumer. Core 0 mainly handles low-level peripherals and filesystem IO, such as opening/reading files and parsing track metadata. Core 1 mainly handles graphics and UI, reading data generated by Core 0 and rendering the appropriate visualizer/interface on the display and LEDs.

Both cores run their own superloop with very few interrupt-based routines. The firmware originally started out as a quick prototyping exercise for some core components, but eventually snowballed into what it is right now, and frankly I think it works alright for the task at hand. The current firmware architecture made it pretty easy to add features and modify existing components.
